# Changelog

## [0.1.11]

- Fixed `Use tsrs (TypeScript 7.1) for WebStorm TypeScript` when used from the Settings dialog. The dialog's already-open `Languages & Frameworks | TypeScript` page kept showing the previous package and wrote it back on OK or Apply, so the switch appeared not to work. The button now reloads that page after switching, and WebStorm's TypeScript service restarts only after the dialog closes. The generated package is refreshed in the VFS and WebStorm's TypeScript 7 detection is invalidated before the setting changes. Package generation is serialized across projects, and the swap keeps a backup of the previous package to restore if activation fails. On musl hosts the musl tsrs build is preferred, and a compiler that cannot be made executable is rejected.
- Migrated from the deprecated `LspServer*` platform API to `LspIntegrationProvider` / `LspClient*` (#26). Plugin Verifier's deprecated-API count drops from 49 to 0. The last four deprecated calls were also replaced: tracer-export and Mermaid file opening, the read action in fix-all, the TypeScript-service restart, and a Jackson field iterator.
- `tsconfig.json` / `jsconfig.json` now get JSON-schema validation and completion for the `@effect/language-service` plugin entry (#22). The schema comes from the workspace's `node_modules/@effect/tsgo/schema.json` when installed, otherwise from a bundled copy of the 0.67.4 schema. Settings validation and `Sync to tsconfig.json` report unknown or mistyped options from the raw-JSON fields as warnings.
- Added `scripts/verify-tsgo-diagnostics-cli.mjs`, a headless check that runs `effect-tsgo diagnostics` (JSON and `github-actions` output) on the LSP fixtures. It asserts the expected Effect findings and directive behaviour, and that the CLI and the LSP report the same diagnostic occurrences per fixture: normalized file, rule name, one-based line, severity, and duplicate counts, with path representations and ordering normalized (#23). CI now runs it together with the real-binary LSP verifier, the instrumentation verifier, and the diagnostic and fix-all platform tests on WebStorm 2026.3.
- Publishing preparation (#24): `PRIVACY.md` now describes the npm registry and tarball requests, the loopback-only Dev Tools server, and the local tracer-export and generated-package files. `THIRD_PARTY_NOTICES.md` lists every bundled runtime library with its license. The Binary mode setting explains that `LATEST` and `PINNED` download executables from npm. The release workflow fails closed when a signing or publishing secret is missing, and builds, verifies, signs, and checks the signature before publishing.
- A ten-reviewer quality pass over the whole project fixed:
  - **Debugger:** instrumentation for remote Node targets; cancelled timed-out evaluations; stale asynchronous captures and attachment state overwriting newer ones; snapshot inspection executing getters; lost nested Context names; ESM source reveal.
  - **Dev Tools:** an EDT refresh loop on the client list; unbounded trace and event retention; selections lost on every update; renders of hidden tabs; an inexact histogram mean; tracer export on the EDT.
  - **Directives and fix-all:** directive-looking text inside strings silencing diagnostics; `skip-file` dropping other rules; a completion crash on a blank first line; per-diagnostic reparsing of the whole file (now cached per document stamp).
  - **Layer Mermaid:** requests sent display columns instead of LSP offsets; file preparation ran on the EDT.
  - **Restart:** could block the EDT behind a download.
  - **Managed binaries:** cache health ignored the external standard library; HTTP requests had no deadlines; failed downloads left temporary files.
  - **Settings:** filesystem discovery on the EDT; the version chooser losing the typed version on cancel; blank diagnostic-rule keys; trimmed environment values.
  - **Release workflow:** duplicate assets; drafts not bound to the validated commit; unrelated drafts deleted.
  - **Verifier scripts and docs:** several fixes.

## [0.1.10]

- Added `Use tsrs (TypeScript 7.1) for WebStorm TypeScript`, a button in `Settings | Tools | Effect` (group `WebStorm TypeScript`) and an `Effect:` action in the `Tools` menu. WebStorm's `TypeScript` package field only accepts a `typescript` 7+ package whose `@typescript/typescript-<os>-<arch>/lib/tsc` sibling holds the compiler, so picking tsrs by hand never worked. The plugin finds tsrs in the workspace's `@tsrs/<platform>` package, the workspace `@effect/tsgo-<platform>` package (`artifacts/tsrs/`), or the managed `@effect/tsgo` cache. It generates a package of that shape under the IDE system directory, linking `lib/tsc` and the standard library to tsrs without touching `node_modules`, then sets `Settings | Languages & Frameworks | TypeScript` to it and restarts WebStorm's TypeScript service. A stock `tsrs.original` left by `effect-tsgo patch --tsrs` is preferred over the Effect-patched binary, so Effect diagnostics are not reported by both WebStorm's TypeScript service and Effect TSGO. A platform test runs WebStorm's own TypeScript 7 package detection against the generated layout.
- Every Effect codemod quick fix now has a top-level `Fix all '<fix title>' problems in file` entry directly in the Alt+Enter list, next to the fix, instead of only in the fix's `…` submenu. The entry resolves the platform's lazy LSP fix placeholder before deciding, and never appears for `Disable <rule> …` directive fixes. The 0.1.8 submenu entry stays.
- "Fix all" now repeats until nothing changes, up to 64 passes, instead of stopping after one. It pulls diagnostics again after each pass and undoes any pass that introduced a new error-severity diagnostic, compared by code and message so errors already in the file do not count. A rejected merged pass is retried one fix at a time, and a single fix that still adds an error is left out. A full inventory of `@effect/tsgo@0.67.4` ran 527 upstream fixtures through the published binary. It found three ways one pass went wrong: merged fixes declaring the same generated name in one scope (`yieldInCallArgument`), overlapping or nested sites that needed a second run (`unnecessaryPipeChain`, `unnecessaryEffectGen`, `layerMergeAllWithDependencies`, …), and upstream fixes that are wrong even alone (for example `catchAllToMapError`, `typeUnionToSchemaUnion`). The same inventory confirmed that all 147 rules surface in the plugin and that every one of the 71 rules with codemods is eligible for fix-all. The run is still one undo step and can be cancelled.
- Replaced the `SimpleListCellRenderer.create(Customizer)` call in the pinned-version picker, which Plugin Verifier reports as scheduled for removal, with the Kotlin UI DSL `textListCellRenderer`.
- The `Pinned version` field in `Settings | Tools | Effect` is now a picker. It lists the exact `@effect/tsgo` versions the workspace already depends on (`node_modules/@effect/tsgo`, the `@effect/tsgo-<platform>` packages in any ancestor `node_modules`, and an exact specifier in the workspace `package.json`), fills in the nearest one when `PINNED` is selected with an empty field, and offers a `Select…` entry that opens a file chooser for an `@effect/tsgo` package directory or its `package.json` to pin that package's version. A typed version still wins. Settings validation and managed resolution now reject anything that is not an exact npm version (a path, range, or URL) with a message that points at `MANUAL` mode, instead of building a bogus registry URL and reporting an npm 404. This change was listed under 0.1.9, but its pull request merged into the 0.1.9 refresh branch after that branch had already landed on `main`, so 0.1.9 builds did not contain it; 0.1.10 is the first release that ships it.
- Added 18 published rule names to Effect diagnostic directive completion: the default-on suggestions with rewrites `effectSucceedWithUndefined`, `failCauseToConstructor`, `flatMapIdentityToFlatten`, `manualMetricTapToTrack`, `mapConstToAs`, `mapSomeCatchNoSuchElement`, `matchBooleanToIsSuccess`, `matchToResultOrOption`, `resultMatchToFromResult`, and `suspendFailToFailSync`; the off-by-default `effectTryWithoutCatch`, `globalJson`, `globalJsonInEffect`, `mapMapErrorToMapBoth`, `provideMergeAllToArray`, `typeUnionToSchemaUnion`, and `yieldInCallArgument`; and `preferEffectString`, which was deferred as unpublished in 0.1.9. The rule-name snapshot test now checks completion against all 147 rules in the `@effect/tsgo@0.67.4` release tag; no rule was removed or renamed.
- Validated managed binary resolution against the published `@effect/tsgo@0.67.4` package. Its schema-5 manifest adds a `beta` TypeScript tag (`7.1.0-beta`, under `artifacts/typescript/7.1.0-beta/`) and a `tsrs` component: an Effect-patched build of the Rust TypeScript port, pinned to the beta's git head, under `artifacts/tsrs/<version>/tsrs`. Exact-`gitHead` matching already selects the beta compiler for a `typescript@7.1.0-beta` workspace and ignores the Rust and Oxlint components, so no production change is needed; regression tests now model this layout.
- Updated the real-binary LSP smoke target to `@effect/tsgo@0.67.4` and `effect@4.1.2`, keeping `typescript@7.0.2`. New fixture cases apply the `Replace with Effect.as` (`mapConstToAs`) and `Replace with Effect.flatten` (`flatMapIdentityToFlatten`) quick fixes. All five verifier lanes also pass when pointed at the packaged `7.1.0-beta` compiler and at the packaged `tsrs` executable, which serves the same Effect LSP over `--lsp --stdio`; it is not a managed selection yet and can be tried through `MANUAL` mode.
- Pinned the runtime smoke fixture to `effect@4.1.2`; `scripts/verify-instrumentation.mjs` now also covers Effect `4.1.2`. The DevTools wire schema and the debugger's private fiber and span keys are unchanged across the 4.0.5 → 4.1.2 delta. Completed fibers now clear their cached span and stack frame after completion observers run, and ended spans ignore late mutations, so the plugin's defect-location capture and tracer decoder need no change.
- Moved the compile target to the WebStorm 2026.2.4 stable build (`262.11879.105`) and the Plugin Verifier targets to the WebStorm 2026.3 GA (`263.7307.202`) and IntelliJ IDEA Ultimate 2026.3 GA (`263.7307.200`) releases, retaining the `262`–`263.*` compatibility range.
